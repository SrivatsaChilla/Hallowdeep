# Working on HallowDeep

How the code is laid out, how to add content, and how to test it. The working notes (setup, the reference data, the
routine before a commit) are in [CLAUDE.md](CLAUDE.md); what matches the original exactly and what is approximated is in
[FIDELITY.md](FIDELITY.md); the co-op plan is in [dev/MULTIPLAYER.md](dev/MULTIPLAYER.md).

Everything hangs off one global, `HD`. `build.py` joins the files in `src/` in a fixed order, with `style.css`, into `dist/hallowdeep.html`.

## How the code fits together

**Engine and screen are separate.** `combat.js` talks to the screen only through `ui.choose`, `ui.fx` and `ui.pace`, so the same engine runs headless in tests. The engine checks every choice it gets back (the count, duplicates, cards that were not offered), so no screen can take more than a card allows.

**The screen patches the page instead of replacing it.** `ui.js` renders HTML strings, then updates the live DOM in place. Elements with a `data-key` (hand cards, enemies, the Energy orb, Guard badges) keep their identity between renders, which is what lets animations run through state changes. Give anything you want to animate a stable `data-key`.

**Players sit in seats.** A fight holds one seat per player. Per-player state (the creature, piles, Energy, Glint, Cells, Clutch) lives on the seat, and the old names (`g.p`, `g.hand`, `g.run`...) point at the active one, so card code written for one player works for any of them. A new field the engine keeps on a fight must be listed in `Combat.SEAT_KEYS` or `Combat.SHARED_KEYS`; `test/sim.js` fails otherwise.

**Effects that move cards go through the engine.** Use `discardFromHand`, `burn`, `drawOne`, `reshuffle`, `create`, `forge` and the rest listed in `dev/TRIGGERS.md`, or triggers like Furtive silently break.

**Gains go through the run.** Relics, cards, potions, Gold, Max HP, removals and upgrades go through `run.addRelic`, `run.addCard`, `run.addPotion`, `run.gainGold`, `run.gainMaxHp`, `run.removeCard` and `run.upgrade`. They report to `run.note()`, and the screen flies each item to where it lives. Touch the arrays directly and the player will not see what they got.

## Adding content

**Cards.** One `card(id, {...})` call. `v` holds base numbers and `up` the upgrade deltas. `text(v, f)` builds the description (use `f.d()` for damage and `f.b()` for Guard so live modifiers show), and `play(g, card, target, v, x)` runs the effect through helpers like `g.attack`, `g.gainBlock`, `g.apply`, `g.drawCards` and `g.burn`.

**Potions.** One `potion(id, {...})` call with `rarity`, `target` (`'self'`, `'enemy'` or `'all'`) and `use(g, target)`.

**Relics.** One `relic(rarity, id, {...})` call with only the hooks it needs. Combat hooks receive `(g, relic, ...)` and run hooks `(run, relic, ...)`. `relic.counter` persists between fights; `g.rs` is per-fight scratch space.

**Monsters.** One `mon(id, {...})` call with `hp`, `moves` and an `ai(e, g)` that returns the next move id. The helpers `cyc` (a fixed cycle) and `rnd` (weighted, with no-repeat and once-per-fight flags) cover most patterns. In a move, `each(g, e)` runs once for every player and `fx(g, e)` once.

**Events.** One `ev(id, {...})` call: `when(run)` is its precondition, `roll(run, rng)` rolls its random values once, and `pages` maps page ids to text and options. An option has a `label`, a `desc(v, run)`, an optional `lock(run, v)` that returns a reason, and `go(run, v)`, which applies the effect and returns the next page id (or `{ fight: 'ENCOUNTER' }`). Card picks go through `run.pending` so the screen and the simulator handle them the same way.

**Enchantments.** A deck card carries `ench: { id, n }`. Fight copies keep it plus a `src` link back to the deck card, so permanent changes stick. An entry in `HD.ENCH` can define `fits`, `kwAdd`/`kwDrop`, `dmgAdd`, `mult`, `blockAdd`, `replay`, `free`, `after` and `extra`. To enchant from a relic or event, push `{ kind: 'enchant', id, n, filter, optional }` onto `run.pending`.

**Heroes.** `HD.CHARS` holds each hero's HP, Gold, Energy, starting deck and relic, card color (pool), and the upgraded versions used by Archaic Tooth and Touch of Orobas. A run is `new HD.Run(seed, charId)`, and every pool lookup goes through `run.color`. The Crowned's, Wirebound's and Unburied's numbers are generated from the data into `src/*_data.js`.

**Card art.** A card's picture comes from its `ART` entry in `src/art.js`: a main motif, an optional second motif, overlay effects and a rotation. Scene colors follow the card type, and small details vary per card from its id. To add a motif, add a 100x100 drawing to `MOTIF`.

## Testing

Run these after every change (CLAUDE.md lists the full routine before a commit):

```bash
python3 build.py
node test/checks.js              # rule checks: damage math, pity, map rules, boss mechanics
node test/triggers.js            # card triggers: Furtive, Burn, end of turn in hand, draw, shuffle, replay
node test/regent_engine.js       # Glint, Temper and card creation
node test/regent_cards.js        # the Crowned's cards, relics and potions
node test/defect_cards.js        # Cells and the Wirebound's cards
node test/necro_cards.js         # Clutch, Knell and the Unburied's cards
node test/mp_checks.js           # multiplayer rules: scaling, shared enemy turns, falling, theft
node test/sim.js 100             # random runs; CHAR=VEILED, CROWNED, UNBURIED or WIREBOUND, ASC=10
node test/mp_sim.js 300          # random 2 to 4 player fights, each replayed from its action log
node test/coop_cards.js          # the 37 co-op cards, co-op card pools, potions thrown to an ally
```

`sim.js` prints a `digest` of every fight, so you can check that a refactor changed nothing, and lists any card, potion or relic that never got used.

Checks against the reference data need a copy of [Spire Codex](https://github.com/ptrlrd/spire-codex) next to this folder (CLAUDE.md has the exact commit):

```bash
node dev/verify.js ../spire-codex/data-beta/v0.111.0/eng          # number parity: expect 0 mismatches
node dev/audit.js ../spire-codex/data/eng ../spire-codex/data-beta/v0.111.0/eng
```

The audit covers every card, relic, potion, event and monster in the data (built, or excluded with a stated reason), numbers, keywords, targets, types, card wording, monster move sequences and starting powers, and the official v0.111 patch notes. It writes `dev/audit_report.txt`.

Browser tests need `pip install playwright pillow` and `python -m playwright install chromium`:

- `python3 dev/qa_devices.py [devices]` plays real fights through the screen at 16 sizes, from 1920x1080 down to a 320x568 phone and a 568x320 phone held sideways, and checks after every action for errors, stuck screens, page scrolling, and anything off screen or covered.
- `python3 dev/qa_resize.py` resizes and rotates mid-fight and runs the same layout check after every change.
- `python3 dev/cardfaces.py` checks every card face prints its keywords and that every term has a tooltip; `python3 dev/handfit.py` checks no card text is cut off in a phone-sized hand.
- `test/extra/` holds more: state fuzzing (`invariants.js`), a full-run click bot (`bot.py`), card, event and keyword checks against the data, and browser tests for phone layouts, card text fit, tooltips, saving and touch.

## Names, versions and saves

**Names.** The game shows the original names by default. The switch on the title screen and the map changes to HallowDeep's own; the choice is saved in the browser. Only names and wording change, never numbers or rules. `src/names.js` is generated: after editing `dev/namemap.json`, run `python3 dev/gen_names.py <codex data/eng dir>`. Before sharing the game publicly, consider defaulting to HallowDeep names (the `'original'` fallback in `HD.boot` in `ui.js`) or dropping `names` and `naming` from `build.py`.

**Versions.** The game follows the v0.111 data. Cards and monsters first written from older data get their v0.111 changes from `src/versions.js` once at load: `v` and `up` merge into the older values, and anything else replaces them. Cards added in v0.111 carry `only: '0.111'`.

**Saves.** The run saves in the browser after every change outside combat and at the start of each fight. Resuming mid-fight restarts that fight from its first turn, and the shuffles replay the same way. Winning or dying clears the save. The run timer at the right of the top bar counts only while a run is open and the page is visible, and is saved with the run. Storage keys stay `hollowdeep.*` so old saves keep working.
